# 논문 브리핑 (오늘의 수의학 논문 브리핑)

내과·외과·영상·응급 분야마다 최근 논문을 앱이 직접 찾아 한국어 카드뉴스 1장씩으로 요약하고, 08:30에 발행해 직원 휴대폰·PC와 세미나실 화면에서 보는 기능. (요약문을 직접 붙여넣는 방식도 보조로 남아 있다.)

## 논문 자동 찾기 (2026-11-25부터 기본)

사용자 결정: 관리자가 요약문을 넣지 않는다. 분야별 1건씩 앱이 찾고, **검수 과정은 없다.**

1. 관리 첫 화면 "논문 찾기"에서 발행 날짜(기본은 다음 빈 날짜)를 고르고 "4개 분야 논문 찾기"를 누른다. 화면이 분야마다 서버를 한 번씩 차례로 부른다(`findBriefingPaper`, 분야당 30초 안팎).
2. **찾기**(`finder/pubmed.ts`): PubMed(NCBI E-utilities, 무료·키 없음)에서 최근 60일(`RECENT_DAYS`)에 올라온, 초록 있는 논문. 검색식은 `finder/sources.ts` 의 `SEARCH_CONFIG`(분야별 전문지 + 종합지는 분야 낱말. 수의: JVIM·J Vet Cardiol·Vet Comp Oncol / Vet Surg·VCOT·J Vet Dent / Vet Radiol Ultrasound / JVECC·Vet Anaesth Analg + 종합지 JAVMA·JSAP·JFMS·Vet J·Vet Rec·Front Vet Sci·BMC Vet Res·Can Vet J·Top Companion Anim Med). 저널을 더할 때는 PubMed 에서 최근 60일 개·고양이 논문이 실제로 잡히는지 먼저 볼 것. 수의학은 개·고양이 논문만, 댓글·사설·정정은 뺀다. 이미 브리핑에 쓴 논문(DOI·제목)도 뺀다.
3. **고르기**(`finder/choose.ts`): 수의학 후보 최대 12건 + 사람 의학 후보 최대 5건을 AI 에게 주고 "개·고양이 진료에 가장 쓸모 있는 1건"을 번호로 고르게 한다. 수의학 우선, 맞는 수의학 논문이 없을 때만 사람 의학. AI 가 목록 밖 번호를 말하거나 실패하면 가장 최근 수의학 논문.
3-1. **무료 원문**: 고른 논문이 PubMed Central 에 있으면(`pmcid`) 본문(JATS XML)을 받아 결과·고찰 위주로 14,000자까지 발췌해 초록과 함께 넘긴다(`parsePmcBody`). 출처 줄에 "무료 원문 기준 요약", 아니면 "초록 기준 요약". 참고문헌의 PMC 번호를 이 논문 것으로 착각하지 않도록 PubmedData 의 첫 ArticleIdList 만 본다. 최근 논문은 PMC 에 늦게 올라와서 초록 기준이 대부분이다.
4. **카드**(`ai-designer.ts` 의 `AI_ABSTRACT_SYSTEM_PROMPT`): 서지 정보 + 영어 초록 → 한국어 카드. 틀은 정해져 있지 않고 논문에 맞게 구성한다. 기존 안전장치 그대로 — 초록에 없는 숫자가 있으면 그 카드는 버린다. 사람 의학 논문이면 "사람 대상 연구"를 주의 구역에 적는다.
5. **출처**: AI 가 쓴 출처는 버리고 PubMed 값으로 덮어쓴다(`candidateSource`: 첫 저자 외 · 저널 · 연도 · 연구 유형 · "초록 기준 요약", 원문 링크는 DOI). 카드 규격에 `source.authors`·`source.basis` 칸이 있다.
6. **저장**: AI 카드면 바로 "검수 완료"로 넣는다 → 그날 08:30 예약(`syncPlan`). AI 가 꺼져 있거나 실패해 규칙 정리로 만든 카드는 초안으로 남겨 발행되지 않는다(화면에 표시).
7. 분야마다 "다른 논문"으로 같은 자리의 논문을 바꿀 수 있다(지금 논문은 다시 고르지 않는다). 자동으로 찾은 논문은 `admin_memo` 가 "자동 찾기 · 분야 · 수의학/사람 의학 · PMID" 로 시작한다.

주의: 대부분 초록만 읽고 요약한다(본문은 유료). AI 에게 인터넷 검색을 시키지 않는다 — 없는 논문·DOI 를 지어낼 수 있다. 운영에서 AI 로 동작하려면 Vercel 에 `BRIEFING_AI_PROVIDER=anthropic` 이 있어야 한다. 매일 저녁 자동 실행(크론)은 아직 없다 — 승인 후 추가.

## 바꾸면 안 되는 규칙

- **논문 1건 = 카드 1장.** 여러 장으로 나누는 구조(slides, pages)는 없다. 카드 규격이 그런 키를 거절한다.
- **필수 입력은 요약문 글상자 1개.** 분야·링크·DOI·메모는 선택(고급 설정).
- **그날 올린 논문 수만큼 발행된다(1~6건).** 그날 논문이 모두 검수돼 있어야 한다. 조건이 안 맞으면 골라서 내보내지 않고 이유를 보여 준다. (새 올리기 화면을 켜기 전에는 예전 고정 규칙 3~4건.)
- **라운딩 화면은 그날 발행된 논문 수만큼만 돈다.** 표지·목차·마무리 장 없음. 진행 표시는 실제 논문 수(`02 / 04`).
- **카드에 없는 내용을 만들지 않는다.** 숫자·출처는 요약문(또는 관리자 입력)에 있는 것만.

## 동작 방식 (환경변수)

전부 서버 전용이고, 없으면 안전한 쪽으로 동작한다. 예시는 `.env.example`.

| 환경변수 | 없을 때 | 있을 때 |
|---|---|---|
| `BRIEFING_AI_PROVIDER=anthropic` (+ `ANTHROPIC_API_KEY`) | 규칙 정리(원문 문장을 그대로 배치) | 실제 AI가 카드를 디자인 |
| `BRIEFING_AI_MODEL` | `claude-opus-5-5` | 지정한 모델 |
| `BRIEFING_INTERNAL_NOTIFY=on` | 직원 알림을 보내지 않고 내용만 기록 | 발행 때 직원 알림함에 1건씩 |
| `BRIEFING_APP_URL` | 네이버웍스 메시지에 경로만 | 전체 주소 |
| `CRON_SECRET` | 크론 경로가 인증 없이 열림 | `Authorization: Bearer` 확인 |

지금 상태는 `/briefing/admin/settings` 에서 볼 수 있다.

### AI 카드 만들기

- AI는 관리자가 "만들기 / 다시 만들기"를 누를 때만 부른다. 직원 조회·라운딩 반복 때는 저장된 카드를 읽기만 한다.
- 모델은 JSON만 돌려주고, 받은 JSON은 카드 규격으로 다시 검증한다.
- 다음 경우 AI 결과를 버리고 규칙 정리로 대신 만든다(화면에 이유 표시, 원본 글과 이전 카드는 보존): 서버 오류, 거절, 응답 잘림, JSON 아님, 규격 불일치, **요약문에 없는 숫자**.
- 요약문·관리자 입력 어디에도 없는 출처(저널·연도·DOI·링크)는 비운다.
- 영문 용어가 요약문에 없으면 버리지는 않고 검수 화면에 경고로 보여 준다.
- 요약문 전체나 AI 응답은 로그에 남기지 않는다(실패 사유 코드만).
- 설치된 SDK(`@anthropic-ai/sdk` 0.98)에는 서버 쪽 거절 대체(fallbacks) 옵션이 없어 쓰지 않았다. 거절은 위 규칙 정리 대체로 처리한다.

## 올리기: 날짜 묶음 + 자동 예약

`supabase/migrate-briefing-planner.sql` 을 실행하면 켜진다(실행 전에는 예전처럼 날짜 작업 화면에서 한 건씩 넣고 직접 예약한다).

- **한 번에 올린 논문들이 그날의 브리핑이다.** 관리 첫 화면에서 발행 날짜(기본은 다음 빈 날짜, 바꿀 수 있다)를 정하고, 논문 칸(탭)마다 요약을 하나씩 붙여넣는다. 칸을 늘리면 그날 나가는 건수가 늘어난다. 날마다 건수가 달라도 된다(1~6건, 최소 건수 없음).
- 설정의 "기본 논문 칸 수"(`briefing_settings.papers_per_day`, 기본 3)는 처음 열어 두는 칸 수일 뿐이다. `min_papers` 칸은 쓰지 않는다.
- **앱은 논문을 다른 날짜로 옮기지 않는다.** 지워도 뒤 날짜의 논문을 당겨 채우지 않고, 발행하지 못하고 지난 날의 논문도 그 날짜에 그대로 남는다(관리 화면이 "발행되지 않고 지났어요"로 보여 준다). 옮기는 것은 관리자가 시켰을 때뿐(`movePaper`: 끌기·옮기기 선택·이 날짜에서 빼기).
- **자동 예약**: 그날 논문이 1건 이상이고 전부 카드가 있고 검수돼 있으면 08:30 발행이 예약된다. 하나라도 검수가 풀리면 예약도 풀린다. 08:30이 지난 오늘 날짜는 예약하지 않고 "지금 발행"으로만 내보낸다.
- **검수는 그대로 있다**(2026-11-15 사용자 결정: 붙여넣을 글의 형식이 아직 정해지지 않아 일단 유지). 넘기면서 검수(PC·모바일·라운딩 세 가지 같이 보기, Enter 로 검수 완료), 경고 없는 카드는 한 번에 검수.
- **날짜 미정** = 날짜가 `9999-12-31`(`QUEUE_DATE`)인 묶음 하나. 날짜에서 뺀 논문이 머문다. 절대 발행되지 않는다. 새 표가 아니다.
- 계산은 `lib/briefing/planner.ts` 의 `settlePlan()`(순수 함수, 테스트 있음), DB 반영은 `lib/briefing/plan-sync.ts` 의 `syncPlan()` → DB 함수 `briefing_apply_plan()`(바뀐 것만, 전부 아니면 전무). **논문을 바꾸는 관리자 액션은 끝에 `settle()`/`syncPlan()` 을 부른다** — 새 액션을 더하면 똑같이 할 것. 관리 첫 화면을 열 때도 한 번 맞춘다.
- 내일부터 예약된 날이 2일치보다 적으면 관리자에게 하루 한 번 알린다(`warnIfStockLow`, 첫 조회 때·크론 공통, `BRIEFING_INTERNAL_NOTIFY=on` 일 때만 실제 알림).
- 같은 글·같은 DOI·같은 제목으로 이미 올린 논문은 "중복 의심"으로 표시한다(막지는 않는다).
- 화면: `components/briefing/admin/planner.tsx`(첫 화면), `review-flow.tsx`(넘기면서 검수), `plan-settings-form.tsx`. 액션: `lib/actions/briefing-planner-actions.ts`.
- 이 방식 전에 잠깐 "대기함에 올리면 앱이 하루 N건씩 날짜를 채우는" 방식이 있었다(커밋 32b6d76). 사용자가 날짜를 직접 정하고 날마다 건수가 달라도 되는 쪽을 골라 바꿨다 — 되돌리지 말 것.

## 발행

- 상태: 초안 → (08:30 예약) → 발행 완료. 알림 상태는 발송 기록(`briefing_notification_logs`)에 따로 남는다.
- **직원에게 보이는 조건**: 발행 완료이거나, 예약 상태이면서 예약 시각이 지났을 때. 그리고 논문이 검수 완료일 때. (DB 접근 규칙과 서버 코드 양쪽에서 같은 조건을 건다.)
- 그래서 **08:30 정각에 보이는 것은 크론과 무관**하다. 크론은 "발행 완료로 표시 + 알림 만들기"만 한다.
- 같은 날짜는 한 번만 발행된다(상태를 조건부로 바꿈). 알림은 채널마다 하루 한 번(`delivery_key` 유니크). 발행 취소 후 다시 발행해도 알림은 또 나가지 않는다.
- 발행된 논문은 **카드의 글만** 고칠 수 있다(오타 — 검수 상태는 그대로, 활동 로그에 `edit_published_card`). 요약 글·순서·삭제는 발행 취소 뒤에.
- 서버가 UTC여도 발행 시각은 한국시간으로 계산한다(`kst.ts`).

### 자동 발행

두 군데서 같은 마무리를 한다. 누가 먼저 하든, 여러 번 하든 결과는 같다.

1. **첫 조회 때**: 08:30 이후 누군가 오늘 브리핑(오늘 화면·내 현황 카드·라운딩)을 처음 열면 예약분을 발행 완료로 바꾸고 알림을 만든다. 크론 없이도 동작한다.
2. **크론** `/api/briefing-publish`: 위와 같은 일 + 오늘 08:30이 지났는데 발행이 없으면 관리자에게 하루 한 번 경고.

크론은 **아직 등록하지 않았다.** 배포할 때 `vercel.json` 에 추가한다:

```json
{ "crons": [{ "path": "/api/briefing-publish", "schedule": "30 23 * * *" }] }
```

(`30 23 * * *` UTC = 한국시간 08:30. Vercel 요금제에 따라 실행 시각이 정확하지 않을 수 있지만, 보이는 시각은 영향받지 않는다.)

## 세미나실 라운딩

- `/briefing/rounding` 을 세미나실 PC 즐겨찾기에 두고, 직원이 "라운딩 대기 모드 시작"을 누른다. 전체화면은 이 버튼을 눌렀을 때만 켜진다.
- 한 장에 머무는 시간: 기본 15초, 5~600초 사이로 직접 입력(그 PC에 기억). ← → 이전·다음 논문, Space 멈춤, F 전체화면, Esc 끝내기.
- 오늘 발행분이 없으면 대기 화면. 발행되면 1분 안에 시작 버튼이 나타난다. 밤새 켜 둬도 날짜가 바뀌면 지난 논문을 저절로 틀지 않는다.
- **지난 브리핑 틀기**: 최근 7일치 발행분을 골라 틀 수 있다(오늘 것이 없으면 대기 화면에 바로, 있으면 "지난 브리핑 틀기"를 펼쳐서). 틀 때 화면 머리에 "지난 논문 브리핑"과 그 날짜가 표시된다.
- 로그인이 서버에서 끝났으면(다른 기기에서 이 계정 로그아웃 등) "로그인이 끝났어요 · 다시 로그인하기"를 보여 준다. 라운딩 화면의 로그아웃은 이 PC만 로그아웃한다.
- **세미나실 전용 계정**: 직원 관리에서 권한을 "세미나실 화면"(`role = display`)으로 만든다.
  - 화면: 로그인하면 라운딩 화면으로만 간다. 다른 주소를 쳐도 라운딩으로 돌려보낸다.
  - DB: `supabase/migrate-display-account.sql` 이 모든 표에 restrictive 정책을 덧붙여, 이 계정은 자기 프로필 1줄과 발행된 브리핑만 읽을 수 있다(사진 저장소 포함 나머지는 읽기·쓰기 불가). 다른 계정에는 영향 없음. 표를 새로 만들면 이 파일을 다시 실행.
  - 서버: 관리자 클라이언트로 읽는 액션(전체 검색·연차·근무표)은 코드에서 이 계정을 거절한다.
- 화면 꺼짐 방지(Wake Lock)는 HTTPS에서만 동작한다. 세미나실 PC의 절전·화면 보호기는 따로 꺼 둘 것.

## 네이버웍스 연결 (보류 — 나중에 이어서 할 때)

지금은 연결하지 않았다. 발행하면 **보낼 내용만** 기록한다(`briefing_notification_logs`, 상태 `mock`). 외부 호출은 없다.

이미 되어 있는 것:

- 메시지 내용: `notify.ts` 의 `buildNaverWorksMessage()` — 논문 3~4건을 **메시지 1건**에 묶은 텍스트(날짜 + 제목 목록 + 오늘 브리핑 링크).
- 중복 방지: `delivery_key = naverworks-group:날짜` 유니크. 실패하면 `failed` 로 남고 다음 실행에서 다시 시도한다(`claimDecision`).
- 미리보기: 관리자 작업 화면의 "네이버웍스 메시지 미리보기", 설정 화면의 알림 기록.

이어서 할 일:

1. 네이버웍스 Developer Console에서 Bot 만들기, 서비스 계정·권한(bot) 발급, 전용 단체방에 Bot 초대, 채널 ID 확인. **최신 공식 Bot API 문서**에서 인증 방식·메시지 규격·요금을 다시 확인할 것(여기 적힌 변수 이름은 자리 표시이며 확정이 아니다).
2. 자격 증명을 Vercel 환경변수에만 넣기(`.env.example` 의 `NAVERWORKS_*` 참고). 소스·채팅·클라이언트 코드에 넣지 않는다.
3. `src/lib/briefing/naverworks.ts` 새로 만들기: 액세스 토큰 발급·갱신, 채널 메시지 1건 전송, 429·일시 오류 시 간격을 늘리며 재시도.
4. `publish-engine.ts` 의 `deliverNotifications()` 2번(네이버웍스) 부분에서, 자격 증명이 있을 때만 실제 전송 → 성공 `sent`, 실패 `failed`(오류 코드·메시지 기록). 없으면 지금처럼 `mock`.
5. `run-publish.ts` 의 `naverWorks` 상태를 연결 여부에 따라 바꾸고 설정 화면 문구 갱신.
6. 테스트 채널로 먼저 보내 보기. 실제 단체방 발송은 승인 후에만.

지킬 것: 하루 1번·메시지 1건(논문마다 따로 보내지 않음), 링크에 토큰을 싣지 않음(로그인해야 열림), 토큰·원문 전체를 로그에 남기지 않음.

## 알려진 한계

- 규칙 정리는 요약문의 문장을 그대로 고르기만 해서, 제목이 첫 문장 그대로 나오는 등 다듬어진 느낌이 덜하다.
- 원문 대조는 숫자·영문 용어·출처의 "글자가 원문에 있는가"만 본다. 의미가 바뀌었는지는 사람이 검수해야 한다(검수 화면에서 원문을 나란히 보여 준다).
- 날짜 묶음 자체를 지우는 화면은 없다(논문만 지울 수 있다).
- 라운딩 화면의 QR 코드(명세의 선택 사항)는 만들지 않았다.
- 브라우저 푸시는 쓰지 않는다(요구 사항).
